进程有自己独立的进程空间（独立内存、指令集等，甚至有独立的操作系统（不同服务器）），但线程是同一个进程空间的并行的执行单元，共享内存。

可以把它类比成一家公司：
- 进程：一家公司，有自己的办公室、资金、档案柜和资源。
- 线程：公司里的员工，共用公司的资源，但各自处理不同工作。
- 多线程：多个员工并行协作。

| 项目      | 进程                     | 线程                 |
| ------- | ---------------------- | ------------------ |
| 本质      | 正在运行的程序                | 进程中的执行单元           |
| 内存      | **有独立的地址空间**           | 同一进程内通常**共享内存**    |
| 资源      | 拥有文件、内存、网络连接等资源        | 使用所属进程的资源          |
| 创建/切换成本 | 相对较高                   | 相对较低               |
| 相互影响    | 一个进程崩溃通常不直接弄坏另一个进程     | 一个线程出严重问题，整个进程可能崩溃 |
| 通信      | 需要 IPC，如管道、socket、共享内存 | 可直接读写共享变量，但要同步     |

一个关键区别是“内存是否隔离”。
两个独立进程：
```text
进程 A：自己的变量 x、自己的堆内存
进程 B：自己的变量 x、自己的堆内存
```
即使它们都叫 `x`，也完全不是同一份数据。进程 A 不能直接修改进程 B 的普通变量。

同一进程中的两个线程：
```text
进程
├─ 线程 1：访问 balance
└─ 线程 2：访问同一个 balance
```
线程共享 `balance`，效率高，但也会产生竞态条件，因此常需要锁。

再补一个容易混淆的点：线程并非“完全共享一切”。同一进程中的线程通常共享代码、全局变量、堆内存、打开的文件等；但每个线程仍有自己的：
- 线程栈（局部变量通常在这里）
- 寄存器状态
- 程序执行位置
- 线程 ID

所以两个线程调用同一个函数时，它们各自的局部变量通常互不干扰；但若它们都修改全局变量或同一块堆内存，就需要协调。
