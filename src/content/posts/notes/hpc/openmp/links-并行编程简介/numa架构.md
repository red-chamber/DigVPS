NUMA 是一种多 CPU / 多插槽服务器常见的内存架构，全称是 Non-Uniform Memory Access，意思是“非统一内存访问”。

> NUMA 把计算和内存划成多个节点；内存并非“同样近”，让线程靠近自己的数据，才能发挥多路、多核机器的性能。

通俗地说：机器里的内存虽然看起来是一整块，但“离不同 CPU 核心的远近”不一样。

```text
CPU 节点 0 ── 本地内存 0
     │
     └──────── 可访问远端内存 1 ───── CPU 节点 1
                                      │
                                      └── 本地内存 1
```

假设线程运行在 CPU 节点 0：
- 访问内存 0：近，速度快，叫本地内存访问。
- 访问内存 1：要经过 CPU 之间的互连，慢一些，叫远端内存访问。
这就是“非统一”：不同内存位置的访问延迟和带宽并不一样。

对比传统 UMA 架构：

| 架构 | 内存访问特点 |
|---|---|
| UMA | 所有 CPU 核心访问任意内存的成本大致相同 |
| NUMA | CPU 访问本地内存更快，访问其他节点的内存更慢 |

为什么要这样设计？因为 CPU 核心越来越多，如果所有核心都争抢一套统一内存控制器和内存总线，容易形成瓶颈。NUMA 把 CPU 和内存分成多个节点，每个节点有更接近自己的内存控制器，因此能提升整体扩展性和内存带宽。它对多线程程序很重要。理想情况是：

```text
线程运行在节点 0 → 它常用的数据也分配在节点 0
线程运行在节点 1 → 它常用的数据也分配在节点 1
```

这样线程尽量访问本地内存，性能最好。反过来，若线程经常被调度到别的 CPU 节点，或者数据总被分配在远端，就会反复发生远端内存访问，延迟更高、带宽也更容易成为瓶颈。
一个很实用的规则是“first touch（首次访问）”：

> 在许多 NUMA 系统上，一块内存实际归属到哪个 NUMA 节点，往往取决于哪个 CPU 节点的线程第一次写入它。

所以高性能程序常见做法是：
1. 先把工作线程固定或倾向运行在某个 NUMA 节点。
2. 让该线程初始化自己后续要使用的数据。
3. 后续也尽量让线程留在同一节点处理那部分数据。

普通桌面程序通常不用特意处理 NUMA，操作系统会尽量调度优化；但数据库、搜索引擎、虚拟化、大型 C++ 服务、AI 推理/训练和高并发服务器，往往会显著受它影响。
