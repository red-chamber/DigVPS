**线程安全性**：一段代码被多个线程同时执行时，是否仍能稳定、正确地工作。如果多个线程同时调用某段代码，不会互相干扰、不会产生错误结果，这段代码就是线程安全的。

例如：
```text
Pease porridge hot.
Pease porridge cold.
Pease porridge in the pot.
Nine days old.
```

OpenMP 会把不同的行分给不同线程：
```c
#pragma omp for schedule(static, 1)
for (i = 0; i < line_count; i++) {
    /* 处理 lines[i] */
}
```
`static, 1` 表示每次分配一行，轮流交给线程。每个线程处理不同的 `lines[i]`，看起来似乎不会冲突。

问题不在文本行，而在 `strtok`：
```c
my_token = strtok(lines[i], " \t\n");

while (my_token != NULL) {
    printf("%s\n", my_token);
    my_token = strtok(NULL, " \t\n");
}
```

`strtok` 的工作方式是：
```c
第一次调用：
strtok(要分割的字符串, 分隔符)

后续调用：
strtok(NULL, 分隔符)
```

例如：
```c
strtok("Pease porridge hot.", " ");
```
先返回 `Pease`，接下来：
```c
strtok(NULL, " ");
```
返回 `porridge`，再调用一次，返回 `hot.`。问题在于：`strtok` 必须记住“上次分割到哪里了”。为了记住这个位置，传统 `strtok` 在函数内部使用了一个静态变量。可以把它想成：`strtok` 内部有一个全局书签“下一次应从哪里继续切分”。这个书签被所有线程共同使用。

## 多线程时如何出错

假设 线程 0 正在分割第 0 行，线程 1 正在分割第 1 行。可能发生 线程 0 内部书签指向第 0 行的下一处位置，线程 1 把同一个内部书签改成第 1 行的位置，线程 0 本想继续处理第 0 行，却可能从第 1 行的位置继续，于是线程 0 可能得到本属于线程 1 的单词，或漏掉某些单词。所以即使每个线程处理不同的字符串，`strtok` 仍不安全。原因不是 `lines[i]` 被共同修改，而是 `strtok` 自己保存了共享的内部状态。

还有一点：
```c
strtok(lines[i], " \t\n");
```
会把分隔符替换成字符串结束符 `'\0'`。

例如：
```text
原始文本：
"Pease porridge hot."

分词之后，内存大致变为：
"Pease\0porridge\0hot.\0"
```
所以 `strtok` 不是纯读取函数，它会修改输入字符串。本例中每条线程处理不同的行，因此通常没有问题；但如果两个线程同时分割同一条字符串，就又会产生竞争条件。

## 正确做法：使用 `strtok_r`

POSIX/Linux 环境中可使用线程安全版本 `strtok_r`，它把原先藏在 `strtok` 内部的“书签”交给调用者自己保存：
```c
char *saveptr;
char *my_token;

my_token = strtok_r(lines[i], " \t\n", &saveptr);

while (my_token != NULL) {
    printf("Thread %d > token %d = %s\n",
           my_rank, j, my_token);

    my_token = strtok_r(NULL, " \t\n", &saveptr);
    j++;
}
```
现在每个线程都有自己独立的 `saveptr`，不会互相覆盖。

`_r` 中的 `r` 表示 reentrant，即“可重入”：多个线程可以同时调用该函数，每个调用者自己保存状态。
