## 避免反复创建线程

冒泡排序的循环依赖很容易看出，不能使用并行优化。另一种排序方法奇偶排序，每一轮分为奇数阶段和偶数阶段，比较相邻元素，顺序错误则交换。可以看出，其内层计算可以使用并行优化（使用 `parallel for`）：
```c
for (phase = 0; phase < n; phase++) {
    if (phase % 2 == 0) {
        /* 偶数阶段：比较 (0,1)、(2,3)、(4,5)... */
        #pragma omp parallel for num_threads(thread_count) \
            default(none) shared(a, n) private(i, tmp)
        for (i = 1; i < n; i += 2) {
            if (a[i - 1] > a[i]) {
                tmp = a[i - 1];
                a[i - 1] = a[i];
                a[i] = tmp;
            }
        }
    } else {
        /* 奇数阶段：比较 (1,2)、(3,4)、(5,6)... */
        #pragma omp parallel for num_threads(thread_count) \
            default(none) shared(a, n) private(i, tmp)
        for (i = 1; i < n - 1; i += 2) {
            if (a[i] > a[i + 1]) {
                tmp = a[i];
                a[i] = a[i + 1];
                a[i + 1] = tmp;
            }
        }
    }
}
```

但是这样排序的每一轮都要反复创建和销毁线程，非常耗时，另一种方法可以沿用之前的线程而非重新创建，即把 `parallel` 放在外层，`for` 放在内层：
```c
#pragma omp parallel num_threads(thread_count) \
    default(none) shared(a, n) private(i, tmp, phase)
{
    for (phase = 0; phase < n; phase++) {
        if (phase % 2 == 0) {
            #pragma omp for
            for (i = 1; i < n; i += 2) {
                /* 比较并交换 (i-1, i) */
            }
        } else {
            #pragma omp for
            for (i = 1; i < n - 1; i += 2) {
                /* 比较并交换 (i, i+1) */
            }
        }
    }
}
```
这样不创建线程，只把循环任务交给已经存在的线程，减少了频繁创建和回收线程的成本。
