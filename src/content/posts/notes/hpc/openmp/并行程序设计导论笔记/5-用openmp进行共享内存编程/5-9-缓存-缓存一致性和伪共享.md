## 1。缓存

CPU 的计算速度远快于访问主内存的速度，所以每个 CPU 核心附近都有更快但更小的缓存（cache）。常用数据会先放进缓存，CPU 下次再访问时就能更快取到。缓存不是一次只读取一个变量，而是一次读取一整块连续内存，称为“缓存行”（cache line）。

例如缓存行是 64 字节，而一个 `double` 是 8 字节：
```text
一个缓存行可容纳 8 个 double

y[0], y[1], y[2], y[3],
y[4], y[5], y[6], y[7]
```
这利用了“空间局部性”：程序访问一个数组元素后，往往很快还会访问附近元素。

## 2。缓存一致性

假设共享变量：
```c
int x = 5;
```
线程 0 和线程 1 都读取过 `x`，于是各自缓存中都可能有一份 `x = 5`。

若线程 0 执行：
```c
x++;
```
它把 `x` 改为 `6`。线程 1 缓存中的旧值 `5` 就不能继续被当作有效数据。缓存一致性协议会让线程 1 的旧缓存行失效，之后线程 1 再读取就必须重新获取更新后的数据。

缓存一致性不能代替：
```c
#pragma omp atomic
#pragma omp critical
#pragma omp barrier
```
如果多个线程无保护地执行 `x++`，即使硬件有缓存一致性，程序仍然有数据竞争。

## 3。矩阵—向量乘法如何并行

计算 $y = Ax$，其中：
- `A`：`m × n` 矩阵；
- `x`：长度为 `n` 的向量；
- `y`：长度为 `m` 的结果向量。

公式是 $y_i = \sum_{j=0}^{n-1} A_{ij}x_j$，串行代码：
```c
for (int i = 0; i < m; i++) {
    y[i] = 0.0;

    for (int j = 0; j < n; j++) {
        y[i] += A[i][j] * x[j];
    }
}
```
外层的每次循环只计算一个独立的 `y[i]`，因此可以用 OpenMP 分给不同线程：
```c
#pragma omp parallel for \
    default(none) private(i, j) shared(A, x, y, m, n)
for (int i = 0; i < m; i++) {
    y[i] = 0.0;

    for (int j = 0; j < n; j++) {
        y[i] += A[i][j] * x[j];
    }
}
```

## 4。为什么矩阵形状不同，速度会不同

三种矩阵：
```text
8,000,000 × 8
8,000 × 8,000
8 × 8,000,000
```
它们的乘加次数都一样，都是约 6400 万次；但运行时间却不同。原因是数据在缓存中的表现不同。例如：
```text
8,000,000 × 8
```
结果向量 `y` 有 800 万个元素。程序不断写入新的 `y[i]`，很多缓存行需要从主内存调入再写回，写缺失较多。而：
```text
8 × 8,000,000
```
`y` 只有 8 个元素，但 `x` 有 800 万个元素。程序需要大量读取很长的 `x`，容易产生读缺失。所以：
> 浮点运算次数相同，不代表运行时间相同；**内存访问方式**和**缓存命中率**同样重要。

## 5。伪共享（false sharing）

伪共享是多线程性能中非常常见、也很隐蔽的问题。假设 4 个线程计算：
```text
线程 0：y[0]、y[1]
线程 1：y[2]、y[3]
线程 2：y[4]、y[5]
线程 3：y[6]、y[7]
```
看上去每个线程写不同元素，完全没有数据竞争。但如果一个缓存行刚好容纳 `y[0]` 到 `y[7]`，那么所有线程都在读写同一个缓存行。当线程 0 更新 `y[0]` 时，缓存一致性机制可能会让其他核心中这整个缓存行失效，之后线程 1 写 `y[2]`，又会让线程 0 的同一缓存行失效，这叫“乒乓效应”，它们并没有真正共享同一个变量，但它们共享了同一条缓存行，因此表现得像是在争抢同一份数据。这就是伪共享。

```text
真正共享：多个线程读写同一个变量
伪共享：多个线程写不同变量，但变量位于同一缓存行
```

伪共享通常不会造成计算结果错误，但会严重拖慢程序。

如何避免伪共享？一种方法是给每个元素填充空间，让不同线程经常写的元素不落在同一缓存行：
```text
原本：
[y0 y1 y2 y3 y4 y5 y6 y7]

填充后：
[y0 + 填充] [y1 + 填充] [y2 + 填充] ...
```
但这会增加内存占用。更常见、更好的写法是：先使用线程私有的局部变量累加，最后只写一次 `y[i]`：
```c
#pragma omp parallel for
for (int i = 0; i < m; i++) {
    double local_sum = 0.0;

    for (int j = 0; j < n; j++) {
        local_sum += A[i][j] * x[j];
    }

    y[i] = local_sum;
}
```

相比原来的：
```c
y[i] += A[i][j] * x[j];
```
这个版本将每次内层循环都写 `y[i]` 变成内层循环只写线程私有的 `local_sum`，最后只写一次 `y[i]`。这样能显著减少不同线程对 `y` 缓存行的争抢。

总结：伪共享不是多个线程写同一个变量，而是多个线程频繁写不同变量，但这些变量挤在同一缓存行中；避免频繁写共享数组、使用私有局部变量累加或填充数据，都能减少这种性能损失。
