将循环分配给线程称为调度，`schedule` 子句用于在 `parallel for` 或者 `for` 指令中进行迭代分配

```c
#pragma omp parallel for schedule(类型, chunk_size)
```

例如：
```c
#pragma omp parallel for reduction(+: sum) schedule(static, 1)
for (int i = 0; i <= n; i++) {
    sum += f(i);
}
```

**chunk**（任务块）即每一小批任务的循环次数

1。**static**：循环开始前，OpenMP 就以轮转的方式决定好每个线程负责哪些迭代
static 的特点，类似于自动缺省：
	- 调度开销低；
	- 分配方式稳定、可预测；
	- 适合每次循环耗时大致相同的情况。

2。**dynamic**：线程不预先固定负责哪些循环；做完当前任务块后，再向 OpenMP 要下一个任务块
	优点：
	- 适合各次循环耗时差别很大的情况；
	- 更容易让所有 CPU 核心保持忙碌，若使用静态分配，拿到慢任务的线程可能长时间忙碌，其他线程却已经空闲。
	缺点：
	- 每次领取任务都有调度开销；
	- chunk_size 太小，例如 dynamic，1，循环次数非常多时开销可能明显
	常见：
```c
// 每次领足够多的迭代
schedule(dynamic, 100)
```

3。guided：同样是动态分配，但策略更聪明，开始任务多，先发比较大的块，后期剩余任务少，再逐渐发小块
	常用于：
	- 总迭代次数很多；
	- 每次循环耗时不均；
	- 希望比 dynamic，1 少一些调度开销。

4。auto：让编译器和运行库决定
	优点是写法简单；缺点是调度行为不够明确，性能可能因编译器、版本或机器不同而变化

5。runtime：运行时决定
	不在代码里固定调度方式，而是在运行程序时决定

以上通常通过环境变量 OMP_SCHEDULE 设置，例如：
```c
export OMP_SCHEDULE="dynamic,10"
./program
```
这样不用重新编译，就能尝试不同策略，适合测试不同方法的性能

如何选择：

| 情况                  | 常用选择                     |
| ------------------- | ------------------------ |
| 每轮循环耗时差不多           | schedule（static）         |
| 每轮耗时差异很大            | schedule（dynamic，chunk） |
| 任务多且耗时不均，希望降低动态调度成本 | schedule（guided）         |
| 希望运行时调参测试           | schedule（runtime）        |
| 不关心具体策略             | schedule（auto）           |
